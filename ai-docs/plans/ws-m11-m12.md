# bodhi-pi WS PoC — M11 + M12

## Context

`bodhi-pi-ws-server` and `bodhi-pi-ws-frontend` reached M10 with full slash-command parity, multi-tenant SQLite, scripted skills, project extensions, and the fs-tools workspace spec. The frontend is a **test app**: its job is to make every observable agent behaviour easy to assert from Playwright.

Two things hold the parity sweep back:

1. **No transport-level visibility.** Every byte to/from the agent crosses one WebSocket, but useChat only exposes the post-parse view. Hidden states the web app captures via `window.__bodhiPiEventLog` have no analogue here.
2. **No cross-session state.** Reload drops the active session; `/model` switches don't persist across reconnects; there is no Stop control while a prompt streams.

M11 lands the foundational state layers (Event Stream + auto-resume). M12 lands the user-facing affordances and ports the deferred specs (cancel, tool-call preview, tool-failure, tool-replay, fs-tools grep, model-switch, cross-provider).

## Two corrections vs the M10 handoff

The handoff in `ai-docs/ws-context.md` flagged "Multi-model config + model switching" as a gap. Verified against current code:

- `/model <id>` is **already wired** to `setSessionConfigOption` (`packages/bodhi-pi-ws-frontend/src/ui/commands.ts:71-94`).
- Anthropic is **already registered** in `packages/bodhi-pi-ws-server/src/models.ts:24` when `ANTHROPIC_API_KEY` is present.

What's missing for that gap is just the **specs** + a working `ANTHROPIC_API_KEY` in the e2e env. Wiring is done.

`bodhi-pi-web/src/agent/session-storage.ts` uses **sessionStorage** with a single global key `"bodhi-pi-web:sessionId"` (no userId scope). ws-frontend has multi-user inputs in Settings (`id`, `email`), so the key shape is a new design — not a port.

## Scope decisions (locked in this planning session)

- **Two milestones, M11 + M12.** M11 = Event Stream + auto-resume. M12 = Stop + tool-call preview + sweep specs + model parity.
- **Event Stream records raw transport frames only.** Tap sits between `wsToStream` and `ndJsonStream`. Two lanes (inbound / outbound), each row has timestamp, direction, parsed `method`/`kind`, raw NDJSON, copy button. No semantic event derivation. Asserted in e2e via `[data-testid="event-row"][data-direction][data-method][data-kind]`. **Always open** while connected — no toggle button.
- **Auto-resume key shape: `(serverUrl, userId) → lastSessionId`** in `localStorage`. Switching either Settings field surfaces a different last session. Stale sessionId on the server falls back to `newSession` (try/catch around `loadSession`).
- **Stop button calls `conn.cancel({sessionId})` only.** No optimistic status pre-flip. Composer stays disabled until the server stops sending chunks and the prompt promise resolves; then `chat.status` flips to `idle` via the existing `finally` in `useChat.send`.
- **`ANTHROPIC_API_KEY` is required, fail-fast.** Copy from `packages/bodhi-pi/e2e/.env.test` into a new `packages/bodhi-pi-ws-frontend/e2e/.env.test`. Both `model-switch.spec.ts` and `cross-provider.spec.ts` rely on `claude-3-5-haiku-latest`. No conditional skip.
- **Tool-call preview enriches the existing M9 extensions assertion** (assert redacted text in card preview) rather than duplicating the spec.

## Out of scope

- Semantic event log (the 19-event-type variant from `bodhi-pi-web`). Raw frame log subsumes the assertion need for now.
- DirectoryGate / FSA picker / mount path display — server holds the FS, operator picks via `--workspace`.
- bodhi-pi-server lib extraction — defer until streamable-HTTP PoC.
- AbortController plumbing through useChat.send. Stop is fire-and-forget per the locked decision.
- Frame log persistence across reload. Buffer is in-memory, cleared on reconnect.
- In-flight prompt collision enforcement. Composer disable + Stop button is the only mechanism.

## Architecture

### Event Stream tap (M11)

The tap lives at the WS-byte boundary. `wsToStream` (`packages/bodhi-pi-ws-frontend/src/lib/ws-stream.ts:14-51`) currently exposes `{readable, writable}` of `Uint8Array`. Wrap both:

- **Readable controller**: in the existing `ws.addEventListener('message', ...)` at L19-23, decode the chunk to a UTF-8 string and call `eventLog.publish({direction: 'inbound', raw, ts: Date.now()})` *before* `controller.enqueue`.
- **Writable.write** at L46-51: decode the chunk to a string and call `eventLog.publish({direction: 'outbound', raw, ts: Date.now()})` *after* the send.

`event-log.ts` is a singleton-per-connection bus: `subscribe(fn)` / `publish(entry)` / `clear()` / `entries()`. Ring buffer capped at 500 entries. Connection lifecycle: `transport.connect` instantiates a fresh log and passes it into `wsToStream`. On WS close the log is preserved (so the panel still shows what happened) but `clear()` is called on the next `connect`.

Lazy-parse: store raw NDJSON only; the panel UI parses on-render to extract `method` / `id` / `params.update.sessionUpdate` for display attributes.

### Auto-resume (M11)

`packages/bodhi-pi-ws-frontend/src/lib/last-session.ts`:

```
key(serverUrl, userId) = `bodhi-pi-ws:lastSession:${serverUrl}:${userId}`
read(serverUrl, userId): string | null
write(serverUrl, userId, sessionId)
clear(serverUrl, userId)
```

Wired in `App.tsx` Connect handler:

1. After `transport.connect` resolves, look up `read(settings.serverUrl, settings.id)`.
2. If present → `useChat.loadSession(sessionId)` inside try/catch. On error → `clear()` + `useChat.newSession()`.
3. If absent → `useChat.newSession()`.

`useChat` writes back via `last-session.write` whenever `currentSessionId` changes (new session, resume success). `/delete <id>` of the active session calls `clear` before redirecting to `/new`.

### Stop button (M12)

In `App.tsx` composer area: if `chat.status === 'streaming'`, render `<button data-testid="composer-stop" type="button" onClick={chat.cancel}>Stop</button>` in place of the Send button. Send button keeps its existing `data-testid="send"` (rename to `composer-send` parity is **not** in scope — keeps existing specs green).

`useChat.cancel()`:
```
const sid = currentSessionId();
if (!sid || !connRef.current) return;
await connRef.current.cancel({ sessionId: sid });
// status flips to idle via the existing finally in send() once the prompt promise settles
```

ws-server side: `session/cancel` is part of the ACP protocol and handled transparently by `AcpAgent` from `createBodhiPiAgent`. No server changes required (verified: no current ws-server code references cancel).

## Risks

- **Anthropic key in git.** `e2e/.env.test` must be gitignored. Verify before the first commit; if the repo's existing `.gitignore` doesn't already match this path, add it. The example file is the only one that goes into git.
- **Stop latency.** Without optimistic pre-flip, the composer stays disabled until the server stops streaming. If `m12-cancel.spec.ts` is flaky, document the expected ceiling (10s) and revisit the optimistic-flip option.
- **Tap perf.** Decoding every chunk to a UTF-8 string in the hot path adds work even when the panel is closed. Mitigation: tap is a no-op pointer until first `subscribe`; `event-log.publish` short-circuits when there are no subscribers. If perf still bites, gate the tap behind an env flag.
- **Stale sessionId resume.** Server returns an error for unknown sessionId — frontend's try/catch must distinguish "session not found" from transport errors so it doesn't disable the Connect button on a normal stale-resume path.
- **Tool-replay timing.** Resuming a session re-emits historical tool calls; the preview field on those replayed cards depends on whether `tool_call_update` history carries `content`. If it doesn't, the tool card renders without preview but with `data-tool-status="completed"` — assertion should not require preview text on replay.
- **Cross-provider model availability.** `claude-3-5-haiku-latest` was the value in `bodhi-pi-ws-server/src/models.ts:24` at planning time. If anthropic deprecates or renames it before this lands, update both the server registration and the spec literals together.
