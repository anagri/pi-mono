# MCP Integration in bodhi-pi (approved via Ultraplan 2026-05-15)

**Scope:** Phase 1 (public + http-streamable) → Phase 2 (stdio) → Phase 3 (OAuth-DCR)
**Runtime matrix:** in-memory · cli · http · ws · browser · chrome-ext

---

## Context

bodhi-pi has no MCP support today. Users need to connect external tool servers (GitHub MCP, filesystem MCP, custom remote MCPs) and have the agent discover and call their tools automatically. The work spans three phases and six runtimes.

---

## Key findings from codebase exploration

### 1. `Agent.state.tools` is the right tool-update surface
`AgentState` (returned by `Agent.state` getter in `packages/agent/src/agent.ts:237`) exposes `set tools(tools: AgentTool<any>[])`. Mutate directly: `session.runtime.piAgent.state.tools = merged`. No session rebuild.

### 2. MCP tools must NOT go through ExtensionRunner
`ExtensionRunner.getTools()` is called once in `buildSessionState` and baked into the piAgent at construction. MCP tools are per-session and dynamic. `McpRegistry` manages a per-session tool pool, and after any connect/disconnect calls `piAgent.state.tools = mergeTools(session.tools, registry.getTools(sessionId))`.

### 3. `session.tools` stays as-is
`SessionState.tools` = builtins + extension tools, frozen at session creation. No changes to `buildSessionState`, `BootstrapDeps`, or `SessionRuntime`. MCP tools live only in `McpRegistry`.

### 4. Hydration sequence: after `buildSessionState`, before first prompt
`agent.ts` calls `this.mcpService.hydrate(sessionId, params.mcpServers)` in `newSession`/`loadSession`/`resumeSession`, after `buildSessionStateFn` returns. Hydration reads kvStore `mcp/*` entries with `lastKnownStatus === "connected"`, merges with `params.mcpServers` (ACP-native), connects in parallel, updates `piAgent.state.tools`. Failures non-fatal: log + emit `mcp_status` event.

### 5. `mcpCapabilities` needs updating
Phase 1 flips `mcpCapabilities: { http: true, sse: false }` in `agent.ts:initialize()`.

### 6. `ExtensionAPI.registerTool` already supports dynamic unregister — no changes needed
`runner.ts:118` returns a teardown `() => void`.

### 7. ACP-native `mcpServers` already passed by the client, ignored by the agent
`client.ts` already sends `mcpServers: params.mcpServers ?? []` on all three session entry-points. Phase 1 threads it through hydration.

## Architecture

```
session creation:  session.tools  =  mergeTools(builtins, extensionRunner.getTools())
                   piAgent starts with session.tools

MCP connect:       McpRegistry adds slug→{client, tools}
                   piAgent.state.tools = mergeTools(session.tools, registry.getTools(sessionId))

MCP disconnect:    McpRegistry removes slug
                   piAgent.state.tools = mergeTools(session.tools, registry.getTools(sessionId))
```

## KV schema — `mcp/<slug>`

```jsonc
{
  "url": "https://mcp.github.com/mcp",        // http transport; absent for stdio
  "command": "npx",                            // stdio transport
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": [{ "name": "GITHUB_TOKEN", "value": "...", "secret": true }],
  "transport": "http" | "stdio",
  "auth": {
    "mode": "public" | "header" | "query" | "oauth-dcr" | "oauth-preregistered",
    "headers": [{ "name": "Authorization", "value": "Bearer …", "secret": true }],
    "queryParams": [],
    "clientId": "…",
    "clientSecret": { "value": "…", "secret": true },
    "tokens": { "access": { "value": "…", "secret": true }, "refresh": { … }, "expiresAt": 0 }
  },
  "lastKnownStatus": "connected" | "disconnected" | "error",
  "addedAt": "2026-05-15T…",
  "label": "GitHub"
}
```

Reuse `maskSecrets`/`containsSecret` from `kv/kv-store.ts`. Client-side reads mask `secret: true` fields; agent-internal reads see plaintext.
